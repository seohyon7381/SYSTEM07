# SYSTEM07
1. 파이프로 왕복
기존 코드는 파이프 하나를 사용하여 부모가 자식에게 문자열을 전달하는 단방향 통신 방식이었다.
이를 수정하여 부모에서 자식으로 문자열을 보내는 파이프와 자식에서 부모로 변환된 문자열을 돌려주는 파이프, 총 2개를 사용하도록 하였다.
부모는 실행할 때 입력한 문자열을 첫 번째 파이프로 전달하고, 자식은 문자열을 읽어 toupper()를 이용해 영문자를 대문자로 변환한다.
변환된 문자열은 두 번째 파이프를 통해 부모에게 전달되며, 부모는 결과를 출력한다.

원리
파이프는 단방향 통신 방식이므로 데이터를 양방향으로 주고받으려면 파이프 2개가 필요하다.
fork()로 자식 프로세스를 생성하고 read()와 write()를 사용해 데이터를 주고받는다.
각 프로세스는 사용하지 않는 파이프 끝을 닫아야 하며, 쓰기 끝을 모두 닫으면 읽는 쪽에서 EOF를 확인할 수 있다.

사용한 프롬프트
기존 1_pipe_basic.c를 수정해서 ./1_pipe "hello world"를 실행하면 부모가 문자열을 자식에게 보내고, 자식은 문자열을 대문자로 변환해 부모에게 돌려주도록 해줘.
파이프 2개를 사용하고, 각 프로세스가 사용하지 않는 파이프 끝을 닫도록 해줘.

2. dup2로 명령 이어 붙이기
기존 코드를 수정하여 실행할 명령어를 입력받고, :를 기준으로 앞 명령어와 뒤 명령어를 구분하도록 하였다.
첫 번째 자식 프로세스는 execvp()로 앞 명령어를 실행하고, 표준출력을 dup2()를 이용해 파이프에 연결한다.
두 번째 자식 프로세스는 파이프의 데이터를 표준입력으로 받아 뒤 명령어를 실행한다.
부모 프로세스는 파이프의 양쪽 끝을 닫고 두 자식 프로세스가 종료될 때까지 기다린다.

원리
파이프는 프로세스 사이에서 데이터를 전달하며, dup2()는 표준입출력을 파이프에 연결하는 역할을 한다.
execvp()는 입력받은 명령어를 실행한다.
부모 프로세스가 파이프의 양쪽 끝을 닫아야 읽기 프로세스가 EOF를 감지하고 정상적으로 종료할 수 있다.

사용한 프롬프트
기존 2_pipe_dup2.c 코드를 수정하여 ./2_pipeline ls -l : wc -l 형식으로 실행할 수 있도록 구현해 줘.
:를 기준으로 두 명령어를 구분하고, fork(), pipe(), dup2(), execvp()를 사용해 첫 번째 명령어의 표준출력을 파이프에 연결하고 두 번째 명령어의 표준입력을 파이프에 연결해 줘.
부모 프로세스는 파이프의 양쪽 끝을 닫고 두 자식 프로세스가 종료될 때까지 기다리도록 해 줘.

3. FIFO로 메시지 주고받기
FIFO를 이용하여 메시지를 주고받는 수신 프로그램과 송신 프로그램을 작성하였다.
수신 프로그램은 FIFO를 생성하고 메시지를 기다리며, 송신 프로그램은 입력한 메시지를 FIFO를 통해 전달한다.
메시지 수신이 완료되면 FIFO 파일을 삭제하도록 구현하였다.

원리
FIFO는 서로 관련이 없는 프로세스 간에 데이터를 주고받을 수 있는 통신 방식이다.
mkfifo()로 FIFO 파일을 생성하고, open()으로 상대 프로세스가 연결될 때까지 기다린다.
송신 프로그램은 write()로 메시지를 전송하고, 수신 프로그램은 read()로 메시지를 읽는다.
통신이 끝나면 close()로 파일을 닫고 unlink()로 FIFO 파일을 삭제한다.

사용한 프롬프트
기존 3_fifo_read.c와 4_fifo_write.c 코드를 수정하여 FIFO를 이용해 메시지를 주고받는 프로그램을 작성해 줘.
수신 프로그램과 송신 프로그램을 각각 구현하고, 수신 프로그램을 먼저 실행하도록 해 줘.
mkfifo(), open(), read(), write()를 사용하여 메시지를 전달하고, 통신이 끝나면 unlink()로 FIFO 파일을 삭제하도록 해 줘.
